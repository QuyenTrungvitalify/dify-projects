# Spec 028 — Fast mode: an opt-in switch that merges Analyze+Spec and tiers the work (keep the Spec gate)

**Status**: Draft (r2 — post-review corrections: analyze.json fold-path + 3-arg call, per-phase `promptFile` conversion, slug-null invariant, post-scaffold fast-revise, honest measurement)
**Effort**: M (one persisted `fastMode` flag + a composer toggle; one `{{DEPTH}}` inject var [+ its `vars()` default]; a merged **Analyze+Spec** draft turn on the fast path — one new lean `draft.md` skill body + a `fastMode`-aware `spec` PhaseDef [`promptFile` becomes `(task)=>string` **for all turn phases** — analyze/implement return their constant; the fast `spec` branch returns `draft.md` **only while `!task.slug`** (pre-scaffold), else `spec.md`; drop `PRIOR_ARTIFACT` when fast] + a one-line `startTask` branch + an extended `spec` verify branch [reads `analyze.json` from `.runs/<taskId>/` and folds it via the real 3-arg `applyAnalysisToTask(task, text, projectsDir)`] + a fast-aware restore + the `features⊆{llm}` auto-guard; a `{{DEPTH}}` conditional in `implement.md` (the only body rendered on both paths — `spec.md`/`draft.md` stay single-valued, §4); tests. **No change to the scaffold timing, the confinement/security model, the validators, the still_failing/import gates, or the Implement + Test turns**). *Touch-point count is broader than "M" suggests — it spans the orchestrator's hottest paths (see Sequencing); the label reflects code volume, not blast radius.*
**Depends on**: [019](019-builder-output-quality-and-lean-roadmap.md) (O2 persisted `pattern`/`features` into `analyze.json`/`task.json`). **Relates to** [027](027-analyze-findquery-truth-and-from-scratch-leanness.md) (same lean ethos; 027 trimmed the from-scratch Analyze *artifact* — this trims its *cost*). **Promotes a bounded slice of fork F-A** (turn-collapse) into scope: only the ①+② merge, which is the collapse that does **not** cross the scaffold/security boundary.

## The pivot from the v1 draft (auto-classify → an explicit switch)

The first draft of 028 derived a `depth` tier from Analyze's persisted `pattern`/`features` (a pure `classifyDepth`). Two problems drove the redesign to an **explicit user switch chosen at build start**:

1. **Auto-classify could never tier Analyze.** `depth` was *derived from* ①'s output, so at ①-render time it was still `standard`. The single largest fixed slice — a whole extra turn's init + context-reload for ① — stayed unrecoverable (the draft's own "① cannot be tiered" row).
2. **Auto-classify had a silent dangerous direction.** A complex requirement whose Analyze happened to emit `features==[llm]` would classify `trivial`, under-build a lint-clean `start→llm→end`, and **nothing downstream would flag it** (the validators check structure, never requirement coverage).

An explicit switch fixes both at once:
- **It is known before ① renders** → `{{DEPTH}}` can be injected into *every* turn, including a merged ①+② turn. **The switch is what unlocks tiering ①.**
- **The machine never guesses.** A lean build happens because a human chose it — an informed decision, not a mis-fire on phrasing. The `classifyDepth` heuristic is dropped entirely.

## Context — the fixed tax on trivial builds

Every build runs the same 4 gated turns (Analyze → Spec → Implement → Test) regardless of complexity. Per-phase wall-clock, **hand-computed from the raw session-transcript timestamps** (the ISO-8601 `timestamp` field in `~/.claude/projects/*/<sessionId>.jsonl`) — one representative run per shape:

| Build | Analyze | Spec | Implement | Total | shape |
|---|---|---|---|---|---|
| simplest (3-node `start→llm→end`, run N1) | 41s | 78s | 69s | **189s** | single-LLM |
| simple chatbot (`start→llm→answer`) | 48s | 75s | 117s | 241s | single-LLM (chat) |
| most complex (9-node pipeline) | 37s | 157s | 371s | **567s** | tool+iteration+2×llm |

> ⚠ **Provenance caveat (r2).** Each row is a **single run (n=1)**, not a median. The campaign transcript tool [`trace_phases.py`](../../.claude/skills/report/trace_phases.py) counts tool-calls but **does not yet extract timestamps** — the seconds above were computed by hand from the raw jsonl. Run-to-run LLM latency is large, so treat these as *illustrative*, not a stable baseline: the real per-shape distribution must be measured (min/median/max, n per cell) before the win in Goal 5 is trusted. The trivial `start→llm→end` Spec time in particular is **not** a fixed "floor" — a second single-LLM corpus build (N3) measured Spec ~99s, so ~78s is a fast sample, not the median.

The implement phase legitimately scales with node count. The recoverable slices are **overhead, not the analysis work**:

- **Per-turn overhead** — Analyze and Spec each pay their own turn-init + a *duplicate* SKILL.md/AGENTS.md read + context load. This is the ~15-25s of fixed cost a *single* merged turn pays once instead of twice. **The merged turn still does Analyze's content-work** (writing `analyze.json`) — so the merge recovers the overhead, **not** the whole ~40s Analyze phase.
- **Spec's `find.py` pattern-search** — `find.py --has …` + reading 1–N `templates/patterns/*.yml` before choosing, even when the answer can only be the single-LLM shape (report-N3 trace: ~40% of the Spec phase's *tool calls* — a call-count share, whose wall-clock share is unmeasured; do not assume it is ~40% of the seconds).

So a trivial `start→llm→end` build pays a fixed slice of turn-init + duplicate context-load + a pattern search it doesn't need. The pipeline is **not complexity-adaptive** — and for the trivial case the user often *knows* it's trivial before the build starts. (How large that fixed slice really is, against the run-to-run variance, is the open measurement question — see Acceptance.)

## Goals

1. **A `⚡ Fast build` switch on the composer.** When on (from-scratch single-LLM builds only), the pipeline (a) merges Analyze+Spec into **one** turn and (b) skips Spec's `find.py` pattern-search + multi-reference reads. When off, the build is **behavior-equivalent to today's 4-turn path** — same turns, same gates, same outputs. *(Not literally byte-identical once B3 lands: B3 wraps `spec.md`/`implement.md` in a `{{DEPTH}}` fence whose `standard` branch is the current procedure **verbatim**, so the rendered instructions are semantically unchanged but the prompt bytes differ — see No-disruption and Sequencing B3.)*
2. **Preserve the load-bearing review — the Spec gate.** Even in fast mode the merged turn STOPS at the Spec gate; the human still reviews `SPEC.md` before any id is minted or YAML written. The under-build catch survives.
3. **Zero change to correctness, security, or the scaffold:** every non-negotiable (mint ids via `generate_id.py`, run the 3 validators, honest `dependencies:[]`+TODO provenance, 13-digit id format, `{{#…#}}` ref discipline, the `.runs/`-only confinement whitelist, the ②→③ scaffold timing) runs **identically** whether fast or not.
4. **Fail-safe to today's behavior:** the switch defaults **off**; an edit-existing or Dify-seed build ignores it (falls back to the 4-turn path).
5. Recover both slices on a fast trivial build **without** touching the complex path. The saving is **the overhead only** — one turn-init + one duplicate SKILL.md/AGENTS.md read + the skipped `find.py` search — **not** the Analyze content-work (which the merged turn still does). *(The `~189s → ~125–140s` figure from an earlier draft was computed off a single n=1 run and is **withdrawn as a headline** — see the Context provenance caveat. The honest target is a **measured median delta** over ≥N fast vs ≥N standard builds of the same prompt, which must exceed the observed intra-shape run-to-run variance to count. If it can't clear the noise, that is itself the answer — see Acceptance.)*

## Non-goals (the leanness boundary)

- **Do NOT collapse Implement into the merged turn.** The ②→③ boundary is where `scaffoldAtSpecGate` runs (`init_project.py` + SPEC.md move) and where the confinement whitelist flips from `.runs/`-only to `projects/<slug>/`. Merging Implement in would force a scaffold *mid-turn* and a **widened security sandbox** (a turn writing `projects/` before the gate). That is the dangerous half of fork F-A — **still deferred**. This spec merges ONLY ①+②, which both write to `.runs/<taskId>/` and never cross that boundary.
- **Do NOT auto-classify.** `depth` is now a user choice, not a derived value. No `classifyDepth`, no dependency on Analyze emitting `features:["llm"]`.
- **Do NOT alter the validators, the still_failing/import gates, or the implement self-fix loop.** Fast mode trims *discovery* (a turn boundary + search/reads), never *verification*.
- **Do NOT offer fast mode on edit/seed builds in v1.** Those run `localEditSeed`/`difySeedScaffoldAndPull` before Analyze; the merged draft assumes from-scratch. The switch is ignored there (fallback = standard 4-turn).
- **Do NOT regress the standard path.** Switch off = every existing corpus build is untouched.

## No-disruption discipline

- **Switch off ≡ today, behavior-equivalent.** `fastMode:false` (the default, and forced for edit/seed/slug builds) → `{{DEPTH}}='standard'`, 4 turns, 4 gates. Every existing corpus build sees **no behavior change**. *Byte-precision:* through B1–B2 the inject var isn't consumed by any body, so the rendered prompts are byte-identical; **B3 changes that** — it inserts a `{{DEPTH}}` fence into `spec.md`/`implement.md` whose `standard` branch is the current procedure verbatim, so the standard path stays *behaviorally* unchanged but its rendered prompt bytes differ. B3 must ship with a render-diff check asserting the `standard` branch text is unchanged (Sequencing B3).
- **The merged turn writes the same artifact shapes to the same paths.** `analyze.json` + `SPEC.md`, both to `.runs/<taskId>/` — exactly the paths ① and ② write today. **This holds because the merged turn runs with `task.slug` still null** (from-scratch, pre-scaffold): the `spec` slot's slug-conditional `artifactRel` ([phases.ts:56](../../apps/builder/server/lib/phases.ts#L56)) then yields the `.runs/` path and `confinementCheck` (slug=null) whitelists `.runs/<taskId>/` only. Fast mode is **from-scratch only** and its merged turn must never run with a slug set (see Design §1 force-off + §3 invariant); a slug-supplied fast build would flip both the SPEC.md target and the confinement whitelist to `projects/<slug>/`. The next phase (Implement, unchanged) consumes `SPEC.md` identically.
- **What fast mode removes vs the dangerous direction — honest about which net catches which:**
  - *Removed, benign:* the **Analyze gate**. In `auto`/`spec_only` it already auto-advances ([orchestrator.ts:218-222](../../apps/builder/server/lib/orchestrator.ts#L218-L222)) → zero loss. In `each_step` the human loses a separate review of `analyze.json` (a near-empty artifact for a trivial build) — folded into the Spec gate review.
  - *Preserved:* the **Spec gate**, the scaffold, the confinement whitelist, and all of Implement + Test's verification. Note the *actual* security controls — the `.runs/`-only confinement backstop ([post-turn.ts](../../apps/builder/server/lib/post-turn.ts)) and the permission-gate hook — **still run on the merged turn** exactly as on ①/② today; the Analyze *gate* is a human review, not a security control, so dropping it removes no enforcement.
  - *The dangerous direction:* a user picks `⚡ Fast build` for a requirement that is **not** actually single-LLM → the merged turn drafts a too-simple `SPEC.md`. Unlike the auto-classify draft, this is now **informed** (the user chose it) AND **caught in `each_step`/`spec_only`** by the surviving Spec gate (an obviously-too-simple SPEC.md is rejectable). It is **only** unguarded in `auto`+fast (no human gate at all) — so v1 adds a cheap **structural sanity-check** there: before an `auto` build auto-advances the merged Spec gate, assert the drafted shape really is the single-LLM one; if not, hard-stop for a human (see Design §5). This **narrows** that gap — it does **not** fully close it: the same merged turn both drafts the SPEC.md and writes the `features` the check reads, so a self-consistent under-build (too-simple SPEC.md *and* `features:["llm"]`) still passes. §5 is therefore contingent on `draft.md` honesty; the residual, and an optional independent cross-check, are stated there.

## Design

**Priority:** **P1** the switch + merged ①+② turn (the 80/20: one fewer turn-reload) · **P2** the Spec `find.py` skip + Implement trim. **Disrupt:** 🟢 additive + default-off — switch-off is unchanged.

### 1. The switch (`fastMode`)

- **State:** add `fastMode: boolean` to [Task](../../apps/builder/server/state/task.ts) + `fast_mode` to `CreateTaskInput`, normalized like `deploy`/`confirmMode` (unknown/missing → `false`). Forced `false` when `seedAppId` **or** `workflow` **or a user-supplied `slug`** is set. *Why slug too:* [`createTask`](../../apps/builder/server/state/task.ts) sets `task.slug` non-null whenever `input.slug` is supplied ([task.ts:208](../../apps/builder/server/state/task.ts#L208)) — and a non-null slug at the merged turn flips the `spec` slot's `artifactRel` to `projects/<slug>/SPEC.md` and opens the `projects/<slug>/` confinement whitelist, breaking the "`.runs/`-only" invariant §3 depends on. Forcing fast off on an explicit slug keeps the merged turn slug-null (the from-scratch case) and mirrors the existing seed/workflow force-off. *(Alternative, if fast+custom-slug is later wanted: give the fast `spec` slot a slug-ignoring `.runs/<taskId>/SPEC.md` `artifactRel` until the Spec gate, mirroring ①'s unconditional `.runs/` path. v1 takes the simpler force-off.)*
- **UI:** a `⚡ Fast build (single-LLM, skip pattern search)` toggle in the composer. Off by default; disabled/hidden when a seed, an existing workflow, **or** a custom slug is chosen. The wiring spans more than "one component" — thread a `fast` field through **all** of: `RunSettings` ([store.ts:36](../../apps/builder/web/src/store.ts#L36), the type that carries `seed`), `Settings` ([types.ts:122](../../apps/builder/web/src/types.ts#L122), the narrower type the `Composer` sees — has **no** `seed`), the `Composer` toggle control, **both** composer render sites (EmptyState + the live dock in [App.tsx](../../apps/builder/web/src/App.tsx)), `CreateTaskBody` ([api.ts:54](../../apps/builder/web/src/api.ts#L54)), and `start()`'s `createTask` call ([store.ts:409](../../apps/builder/web/src/store.ts#L409)). The **disable-on-seed/slug rule must live where `settings.seed`/`settings.workflow`/`settings.slug` are in scope** (App/store — the `RunSettings` layer), **not** inside `Composer` (whose `Settings` type doesn't carry `seed`).

### 2. `{{DEPTH}}` inject var (sourced from the switch)

`DEPTH = task.fastMode ? 'trivial' : 'standard'`. Plumb it like `{{REQUIREMENT}}`/`{{DEPLOY}}`, **and add `DEPTH: 'standard'` to the base token map in [phases.ts](../../apps/builder/server/lib/phases.ts) `vars()`** so the "every known token is always substituted, no stray `{{TOKEN}}` survives" contract holds. Because the switch is known at start, `{{DEPTH}}` is injectable into **every** turn — including the merged draft turn (this is the pivot's payoff over auto-classify).

### 3. The merged Analyze+Spec draft turn (fast path only)

A new lean skill body `draft.md` at `.claude/skills/dify-build/draft.md` — a single bounded turn that does ①'s from-scratch analysis AND ②'s spec authoring for the single-LLM shape, reading SKILL.md/AGENTS.md **once**:

- Writes `analyze.json` to `.runs/{{TASK_ID}}/` (`seed:null`, `pattern:custom`, `features:["llm"]`) — the honest from-scratch content, in the shape 027 defined. **Divergence from `analyze.md` (must be stated in `draft.md`):** 027/`analyze.md` make `features` **optional** ("you MAY add features") on the from-scratch path; **`draft.md` makes `features` MANDATORY** — a pure single-LLM draft **MUST** write exactly `features:["llm"]`, and a draft that finds the requirement is *not* pure single-LLM **MUST** write the real needed set (e.g. `["llm","iteration"]`) and flag it in Open Questions rather than forcing `start→llm→end`. This is load-bearing: the §5 `auto`+fast guard reads `task.analysisFeatures`, which [`applyAnalysisToTask`](../../apps/builder/server/lib/analysis.ts#L93) only populates from a **non-empty** `features` array — so an omitted/empty `features` hard-stops every `auto`+fast build (fail-safe, but it defeats the auto path for honest trivial builds unless `draft.md` always emits `features`).
- Writes `SPEC.md` to `.runs/{{TASK_ID}}/` directly from the single-LLM shape (`start→llm→end`, or `→answer` for advanced-chat — inferred from the requirement), **without** running `find.py` or reading `templates/patterns/*`.
- Still surfaces the model/plugin TODO + open questions, and **proposes `slug`/`name` if `{{SLUG}}` is empty** (the scaffold needs them).
- **STOPs at the Spec gate.** No ids minted, no YAML, no `init_project.py`.

**Mechanism — the `spec` PhaseDef becomes `fastMode`-aware (no new Phase enum, no bespoke turn path).** `injectVars`/`artifactRel` already take `task`; **`promptFile` does NOT — it is a static `string` today** ([phases.ts:18](../../apps/builder/server/lib/phases.ts#L18)), so converting it is a shared-type change (below). The merged turn reuses the `spec` phase slot with fast-conditional pieces:
- **`phases.ts` — `promptFile` becomes `(task) => string` for ALL turn phases (shared-type change).** The field is one type on `PhaseDef`; if only `spec` becomes a function, the `analyze`/`implement` string literals ([:44](../../apps/builder/server/lib/phases.ts#L44),[:69](../../apps/builder/server/lib/phases.ts#L69)) stop type-checking **and** the unconditional call `phase.promptFile!(task)` would throw "not a function" on the standard Analyze/Implement turn. So convert **every** turn-phase `promptFile` to `(task)=>string`: `analyze`/`implement` return their constant; `spec` returns **`task.fastMode && !task.slug ? draft.md : spec.md`**. (`test` is `kind:'backend'`, `promptFile` stays `undefined`, never dereferenced — `runPhase` only handles `analyze|spec|implement`.) The **`!task.slug`** guard is what makes a *post-scaffold* spec-revise fall back to the slug-aware `spec.md` (see Restore); pre-scaffold (slug null) it is `draft.md`. `injectVars` → add `DEPTH`, and **drop `PRIOR_ARTIFACT` when `fastMode`** (analyze.json does not exist at the merged turn's start — the turn *writes* it; `draft.md` must not consume `{{PRIOR_ARTIFACT}}`, which renders to the `vars()` default `""`). `runPhase`'s `readFile(phase.promptFile!)` becomes `phase.promptFile!(task)`.
- **`startTask`:** `fastMode ? runPhaseAndGate(task, 'spec', ctx) : runPhaseAndGate(task, 'analyze', ctx)` (seed/edit/slug already forced `fastMode:false`, so `task.slug` is null here → the merged `draft.md` runs). `runPhase` sets `task.phase='spec'` and emits, so the UI shows the (merged) Spec phase running from the start and the Analyze gate is simply never emitted. *(UX note: [`phaseStates`](../../apps/builder/web/src/store.ts#L90) derives the 4-phase strip from `PHASE_ORDER.indexOf(task.phase)`, so with `phase='spec'` from the start the **Analyze pill renders `done`** — expected, since `analyze.json` IS written by the merged turn — with no separate Analyze run/gate card. No `phaseStates` change needed; document it so QA doesn't read it as a bug.)*
- **Merged verify** (`verifyPhase`, `spec` branch, when `fastMode`): the `①/②` branch's existence check keeps targeting **SPEC.md** via `phase.artifactRel(task)` (slug null → `.runs/<taskId>/SPEC.md`). Additionally, fold `analyze.json` — which lives at a **different, non-`artifactRel` path**: `apps/builder/.runs/<taskId>/analyze.json` (after `relocateRunArtifacts`; the `spec` slot's own `injectVars` already computes this exact path as `runArtifact(t,'analyze.json')`, [phases.ts:62](../../apps/builder/server/lib/phases.ts#L62), so no new export is needed). Read it and call the **real 3-arg** `applyAnalysisToTask(task, await readFile(analyzeAbs,'utf8'), projectsDir)` inside a try/catch mirroring [orchestrator.ts:424-427](../../apps/builder/server/lib/orchestrator.ts#L424-L427) (it `JSON.parse`s and **throws** on invalid JSON → park at error, same as the analyze branch). This folds `pattern`/`features` onto the task (feeds §5). Set `task.artifacts.analyze` explicitly; `task.artifacts.spec` is **already** set by `runPhase` after a non-error verify (`artifacts[sessKey]`, `sessKey==='spec'` → SPEC.md), so only `.analyze` is the net-new write. On success it stays the simple ①/② outcome (`success`/`error`); no lint/yaml (that is ③).
- **`maybeAutoAdvance`** honors `confirmMode` at the `spec` boundary unchanged: `auto` → advance to scaffold+Implement; `spec_only`/`each_step` → pause (both already pause at `spec` — [boundaryAutoAdvances](../../apps/builder/server/lib/orchestrator.ts#L218)). So fast mode composes with all three confirm modes with no change to `boundaryAutoAdvances`. The **one** new branch in `maybeAutoAdvance` is the §5 `auto`+fast guard (an early-return after the existing `gate.flag` checks) — see §5; the earlier phrasing "no change to that function" is corrected to "no change to `boundaryAutoAdvances`; one added early-return in `maybeAutoAdvance`."
- **`sessionIds`** stores the merged session under `spec`. A pre-scaffold `/reply` "Edit spec" (slug still null) resumes it via the fast `promptFile` (`draft.md`) — the session already holds the analyze context. A **post-scaffold** revise resolves to `spec.md` (slug set → the `!task.slug` guard), which is correct: analyze.json exists on disk, `{{PRIOR_ARTIFACT}}` is valid, and `spec.md` writes SPEC.md to `projects/<slug>/` matching the post-scaffold `artifactRel`.
- **Restore (fast-aware) — two cases:** (1) cancelled *at* the merged Spec turn (`phase==='spec'`, slug still null): `restoreTargetPhase('spec')` returns `analyze`, but there is **no** Analyze gate to land on — restoring there raises a phantom Analyze gate. The restore route ([tasks.ts:393](../../apps/builder/server/routes/tasks.ts#L393)) must treat `fastMode && phase==='spec' && !task.slug` like the first-phase case (`target=null` → reopen as a retryable `error`, "Retry to re-run the merged draft"). (2) cancelled *at* `implement` (auto-advanced past the Spec gate, so the scaffold already ran and `task.slug` is set): `restoreTargetPhase('implement')='spec'` re-parks the normal Spec gate — and because slug is now set, the `!task.slug` guard makes "Edit spec" resolve to the slug-aware **`spec.md`** (not `draft.md`), which writes/reads SPEC.md at `projects/<slug>/` in agreement with `artifactRel` and the scaffold move. **Without the `!task.slug` guard**, this path would re-run `draft.md` (which writes `.runs/`) while verify `stat()`s `projects/<slug>/SPEC.md` → the human reviews one file while Implement consumes another. The `!task.slug` guard is what closes this; cover it in B4.

### 4. Per-phase depth profile (what fast mode changes — everything else identical)

| Phase | fast mode does LESS | UNCHANGED (non-negotiable) |
|---|---|---|
| ①+② **merged draft** | **one turn instead of two** — recovers the *overhead only* (turn-init + a duplicate SKILL.md/AGENTS.md read), **not** the Analyze content-work; **skip `find.py` + reading `templates/patterns/*`**; emit `analyze.json` + minimal single-LLM `SPEC.md` directly; **skip the Analyze gate** | writes honest `analyze.json` (`seed:null`/`pattern:custom`/**mandatory** `features:["llm"]`); a real `SPEC.md` (node table + var-flow + plugin TODO + proposed slug/name); **the Spec gate**; **no ids, no YAML, no scaffold** |
| ③ Implement | skip re-running `find.py` (shape already fixed); shorter node table → fewer steps. ⚠ **"read only the single-LLM reference" is aspirational until B3 pins a reference file** (none ships today — see B3); until then the ③ trim is only "skip re-running `find.py`". | mint ids via `generate_id.py`; **all 3 validators**; the still_failing gate; honest `dependencies:[]`+TODO; **the ②→③ scaffold, unchanged** |
| ④ Test | — | backend lint + gate, unchanged |

**Where the `{{DEPTH}}` fence lives — not all three files carry both branches** (each body only ever renders under one DEPTH value, so a two-branch fence is dead code in the single-valued bodies):
- **`draft.md`** renders **only** on the fast path (`spec` promptFile picks it only when `fastMode`), so `{{DEPTH}}` is **always `trivial`** there → `draft.md` is the **trivial-only** merged body, written straight (no `Otherwise` branch).
- **`spec.md`** renders **only** on the standard path (picked when `!fastMode`), so `{{DEPTH}}` is **always `standard`** there → keep it as the current full pattern-search procedure (no `If trivial` branch needed).
- **`implement.md`** is the **only** body rendered on **both** paths (③ runs in fast and standard alike), so it legitimately carries **both** branches:
  > **If `{{DEPTH}}` is `trivial`:** the shape is a single-LLM transform with no plugins/branches/iteration — do NOT re-run `find.py` or read the patterns dir; build directly from the fixed single-LLM shape. *(The "read only the single-LLM reference" trim needs a named reference file — deferred to B3, see below.)*
  > **Otherwise:** (the current full procedure, verbatim).

### 5. Safety — the `auto`+fast structural sanity-check

`auto`+fast is the one configuration with **no** human gate. Before `maybeAutoAdvance` auto-confirms the merged **Spec** gate under `auto`, run a cheap **machine-readable** assertion (pure, no turn): read `task.analysisFeatures` (folded onto the task by the merged verify's `applyAnalysisToTask`) and require `features` PRESENT, NON-EMPTY, and ⊆ `{llm}`. If it is **not** — i.e. the merged draft itself found the requirement needs iteration/tool/http/branch/etc., **or** it wrote no `features` at all — **hard-stop** the auto-advance and park at the Spec gate for a human.

**Exact mechanism (pins the one new control-flow branch).** The guard is neither `boundaryAutoAdvances` (a mode/phase table) nor a `gate.flag` — it is a content assertion, so it lives as an **early `return` in `maybeAutoAdvance`, after the existing `gate.flag` checks** ([orchestrator.ts:207-209](../../apps/builder/server/lib/orchestrator.ts#L207-L209)):
```
if (task.fastMode && task.phase === 'spec' && !featuresSubsetOfLlm(task.analysisFeatures)) {
  task.fastReviewNote = 'Fast build found a non-trivial shape — review before continuing';
  await emit(task, ctx); return;   // leave the already-parked awaiting_confirm Spec gate as-is
}
// featuresSubsetOfLlm(f) := Array.isArray(f) && f.length > 0 && f.every(x => x === 'llm')
// NOTE: it must return FALSE for undefined/[] — do NOT write a naive "every ∈ {llm}" check,
// since ∅ ⊆ {llm} is vacuously true and would skip the hard-stop (the exact fail-safe case §5 wants).
```
It does **not** add a new `gate.flag` (that would touch `gate.ts`/`task.ts`/the UI flag handling — out of scope, and the Effort line keeps the still_failing/import gates unchanged). It reuses the already-set `awaiting_confirm` Spec gate; the human just isn't auto-advanced past it. Carry the note on a new optional `task.fastReviewNote` (precedent: `slugNote`/`patternAdvisory`), and render it on the Spec gate card (name it here so the UI work is in scope). In `each_step`/`spec_only` the Spec gate already pauses, so this branch is only reachable — and only matters — under `auto`.

Checking `task.analysisFeatures` (structured JSON) rather than parsing `SPEC.md`'s free-form markdown node table is the load-bearing choice: it is the same signal 019/027 persist, and it is robust where a markdown-table parse would be brittle. **The check is not independent of the thing it checks:** the *same* merged turn both drafts the SPEC.md and writes the `features` array the guard reads (see §3 — `draft.md` MUST emit truthful `features`). So it **narrows, but does not fully close,** the `auto`+fast gap: a self-consistent under-build (a too-simple SPEC.md *and* a matching `features:["llm"]`) still auto-advances. This is an improvement over the auto-classify draft (which had no such check at all) and it is **fail-safe on the honest-but-missing case** (no/empty `features` → hard-stop), but it is **contingent on `draft.md` honesty**, not a guarantee. *(Optional stronger cross-check, deferred: assert the drafted SPEC.md node table is exactly `start`/`llm`/`end`|`answer` when `features==["llm"]`, so a features-vs-shape mismatch is caught even when the draft lies — spec.md already mandates a node table. Left out of v1 to keep the guard pure/no-parse; trigger: an observed self-consistent under-build in `auto`.)*

## Considered & deliberately NOT done

- **F-A (remaining) — collapse Implement into the merged turn (Analyze+Spec+Implement in one turn).** The bigger win (~45-50%) but it forces the scaffold *mid-turn* and a **widened confinement/security sandbox** (a turn writing `projects/<slug>/` before the gate — the load-bearing S1 fix of spec 015/024), plus it loses the Implement `/reply` granularity and the still_failing checkpoint. **Deferred.** **Trigger:** 028 lands and the measured fast-build time is still judged too high. 028 keeps this open by leaving the ②→③ boundary (scaffold + confinement flip) untouched.
- **Auto-classify (`classifyDepth`).** The v1 draft's derived-depth approach. Rejected in favor of the explicit switch: the switch is known pre-①(so it can tier the merged turn), never mis-fires on phrasing, and needs no dependency on Analyze emitting `features:["llm"]`. (Kept here as the documented alternative, not the design.)
- **F-B — mode-aware depth (`auto` collapses gates further).** Superseded: fast mode already drops the Analyze gate for everyone and the §5 sanity-check handles `auto`'s missing review. Collapsing the Spec gate in `auto` too is the F-A Implement-merge in disguise — deferred with it.
- **F-D — share context across turns (cache AGENTS.md/skill/patterns reads).** Attacks the per-turn reload directly, but fights the "each phase is an independent resumable turn" contract (resume, gating, `--resume` session ids). The ①+② merge captures the same reload saving for the two cheapest phases without that fight. Out of scope for the rest.
- **Raising depth on complex (extra validation passes / a refine loop).** The symmetric idea (do MORE when complex). Out of scope — this spec only *removes* waste on trivial.

## Acceptance

- **Win — the falsifiable gate is structural, the seconds are informational.** A fast build (`fastMode:true`, e.g. `中国語を英語に翻訳…`) MUST: run **one** merged Analyze+Spec turn (not two); **not** invoke `find.py` in that turn; STOP at the **Spec gate** (the Analyze gate never appears); write `analyze.json`+`SPEC.md` under `.runs/<taskId>/` only. These are deterministic pass/fail checks (n=1-robust). The **timing** is a *measured outcome, not a pass/fail threshold*: report the **median over ≥N (≥3, ideally ≥5) fast builds vs ≥N standard builds of the same prompt**, with min/max and the sample count, and require the median fast<standard delta to **exceed the observed intra-shape run-to-run variance** (compute that variance from the runs you collect). If the delta can't clear the noise, that is a real result — record it, and it is the F-A trigger discussion, not a silent "pass".
- **No regression — correctness:** that same fast build's Implement still mints 13-digit ids, runs all 3 validators, and exits **0/0/0**; the produced `main.yml` still meets the requirement's `must_do` (verified via `/report`).
- **No regression — security/scaffold:** the merged turn (running with `task.slug` null — the from-scratch invariant of §1/§3) writes only under `.runs/<taskId>/`; the ②→③ scaffold (`init_project.py` + SPEC.md move) and the confinement whitelist are unchanged from today's `fastMode:false` path.
- **No regression — standard:** `fastMode:false` (default, and forced for any seed/edit/slug build) runs the full 4-turn, 4-gate path with the pattern-search unchanged; the B3 render-diff confirms `spec.md`/`implement.md`'s `standard` branch text is the pre-B3 procedure verbatim (behavior-equivalent, per Goal 1).
- **Fail-safe (`auto`+fast):** if a fast build's merged draft concludes a non-single-LLM shape (`features ⊄ {llm}`), **or writes no `features`**, the `auto` path does NOT auto-advance — it hard-stops at the Spec gate for a human with `task.fastReviewNote` set (§5).
- **Measurement method:** per-phase wall-clock = (last − first `timestamp`) per `sessionIds[phase]`, read from the raw `~/.claude/projects/*/<sessionId>.jsonl`. **This needs building** — [`trace_phases.py`](../../.claude/skills/report/trace_phases.py) currently reads those jsonl files but extracts no timestamps; add a timestamp-diff mode (or a small sibling pass) and emit the median table with the source `sessionIds`. Do **not** cite hand-computed seconds as "measured by the campaign tool" until this exists.
