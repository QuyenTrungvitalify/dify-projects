# Linter-rule candidates (spec 050 D2a)

Mechanical, checkable rules surfaced by promotions/incidents, waiting to be folded into an
EXISTING linter (013/049 discipline — never a new script). One bullet per rule; dedup key is
the exact rule statement. When a rule ships, move its bullet to the shipping spec's log.

- environment_variables entries must use 'name:' (not 'variable:', the start-node input shape) — Dify import 400s 'missing name' — cite: `api/factories/variable_factory.py build_environment_variable_from_mapping`
- A downstream ref to a bowenliang123/md_exporter md_to_xlsx (or md_to_csv/md_to_docx) tool node MUST select its `files` field (value_type array[file]); the tool node declares NO outputs: block, so a ref to `.text`/`.output`/`.result` on it is a dangling ref. — cite: `docs/runtime-supplement.md §1-supplement (md_to_xlsx tool node — no outputs:, downstream reads `files`)`
- A Code node feeding md_text of md_to_xlsx must build a Markdown TABLE string that includes both a header row and the `| --- |` separator row (line 2); a bare list of `|`-lines yields zero columns in the produced .xlsx. — cite: `docs/plugin-capabilities.md (md_exporter Markdown-table inline-formatting) + projects/_drafts/exel_pdf_url_excel build`
- Code nodes must not import openpyxl (or other non-sandbox modules) to build spreadsheets; use the Code→Tool md_to_xlsx bridge instead. — cite: `docs/runtime-supplement.md §1-supplement (openpyxl confirmed-missing; probe test_openpyxl_feasibility.yml)`
- A code node that consumes a document-extractor's `text` output must handle BOTH array[string] and a bare string (isinstance(x, list) guard) — document-extractor returns ArrayStringSegment when its input file variable is a list (multi-file / is_array_file) but a plain string for a single File, so code that assumes one shape crashes on the other. — cite: `vendor/dify-src/api/core/workflow/nodes/document_extractor/node.py _run (list input -> ArrayStringSegment; single File -> str)`
- An LLM node whose prompt references {{#context#}} MUST set data.context.enabled: true and data.context.variable_selector to an upstream knowledge-retrieval node's `result`; otherwise {{#context#}} resolves empty and the model answers with no retrieved evidence (imports clean, fails at runtime). — cite: `vendor/dify-src/knowledge-retrieval-to-llm-context-binding`
- A trigger-schedule node must set an explicit `timezone:` — a missing timezone defaults to UTC, so an X:00 JST schedule silently fires 9h off. — cite: `incident: chatwork_1_10_20 build (spec 057) / vendor/dify-src schedule trigger default UTC`
- environment_variables entries must use the key `name:` (not `variable:`) or the DSL import fails. — cite: `incident: spec 057 env-var import failure`
- A DSL that contains any `type: tool` node must carry a NON-EMPTY top-level `dependencies:` array, or Dify never prompts to install the plugin and the tool node fails at runtime with no explanation. — cite: `vendor/dify-src/api/services/app_dsl_service.py:272-285`
- An `iterator_selector` feeding a `type: iteration` node should be capped (<=30 items) upstream — the iteration node has a 30-item ceiling. — cite: `docs/constraints §2 iteration max`
- In a single-LLM passthrough (start -> llm -> end), the end node's value_selector must reference the llm node's 'text' output, and the llm's user-role prompt must reference the start variable via {{#<start_id>.<field>#}} — a broken ref fails the linter. — cite: `projects/_drafts/ai_1_user_input/workflows/main.yml (source build)`
- end node output value_selector for an LLM result must reference the field `text` ([<llm_node_id>, text]), not `output` — cite: `vendor/dify-src — LLM node output schema exposes `text`; source build 1785372822750 end node uses ['1785221390571', text]`
- A trigger-schedule node must set an explicit `timezone:` (e.g. Asia/Tokyo); Dify defaults to UTC, silently shifting the fire time. — cite: `projects/_drafts/chatwork_1_10_20/workflows/main.yml:258 (trigger-schedule)`
- environment_variables entries must use the `name:` key, not `variable:`, or DSL import fails. — cite: `projects/_drafts/chatwork_1_10_20/workflows/main.yml:23 (spec 057)`
- A workflow containing any `type: tool` node must carry a NON-EMPTY top-level `dependencies:` array listing each tool plugin (version-pinned identifier + public hash), or Dify never prompts to install and the tool fails at runtime. — cite: `vendor/dify-src/api/services/app_dsl_service.py:272-285`
- A tool node's `provider_type` must be `builtin` (not `plugin`) and `provider_name` must be the full 3-segment path identical to `provider_id`; a 2-segment value raises ValueError in Dify's GenericProviderID. — cite: `vendor/dify-src/api/core/tools/tool_manager.py:985-987`
- An llm node doing long-form generation must set `completion_params.max_tokens` explicitly, or the body is truncated at the provider default. — cite: `projects/_drafts/chatwork_1_10_20/workflows/main.yml:919-920`
- In advanced-chat mode (app.mode == 'advanced-chat'), the terminal node MUST be type 'answer', not type 'end' — the answer node is what streams the reply into the chat window. — cite: `incident: source build projects/_drafts/x_y_d_ng (Chatbot Hỏi–Đáp Cơ Bản) — chat-mode app terminates in answer node`
- In advanced-chat mode, the user message arrives on system variable sys.query, so the start node carries no custom input variable (variables: []); a required start variable would make it a form-style workflow instead. — cite: `incident: source build projects/_drafts/x_y_d_ng — start node has variables: [] and the LLM/user turn reads {{#sys.query#}}`
- In an app with mode: advanced-chat, the terminal node must be type `answer`, not `end`. — cite: `vendor/dify-src — advanced-chat apps end in an Answer node; End node is workflow-mode only`
- In advanced-chat, the chat message is read from the system variable {{#sys.query#}}; the start node must declare no input variable for a pure chatbox. — cite: `vendor/dify-src — advanced-chat sys.query`
- A code node consuming document-extractor output (is_array_file:true → array[string]) must index element [0] defensively before parsing, since the array may be empty. — cite: `projects/_drafts/t_i_c_m_3/workflows/main.yml node 1785081237960`
- A code node must not import third-party libraries (pandas, matplotlib, numpy) — only the Python standard library is available in the Dify code runtime; charts must be emitted as an echarts option JSON string, not rendered images. — cite: `projects/_drafts/t_i_c_m_3/SPEC.md acceptance-criteria`
- An `end` node output reading an `llm` node must use value_selector [<llm_id>, text] — the LLM emits its result on the `text` field; selecting `output` (or any other key) resolves to empty with no lint error. — cite: `vendor/dify-src/api/core/workflow/nodes/llm — LLM node output key is `text``
- An `end` node output whose source is an `llm` node must use value_selector [<llm_node_id>, text] — the LLM text output field is literally `text`, not the output variable's name. — cite: `projects/_drafts/y_u_c_u/workflows/main.yml end node (variable: summary, value_selector ['1785724212664', text])`
- Every `{{#<node_id>.<field>#}}` reference in a prompt_template must resolve to an existing upstream node id and its declared field (here the start node's `input_text`). — cite: `projects/_drafts/y_u_c_u/workflows/main.yml llm user turn '{{#1785724212662.input_text#}}'`
- An `end` node output whose value_selector points at an `llm` node must reference the field `text` (not `output`/`result`); any other field name on an LLM source returns empty at runtime. — cite: `vendor/dify-src — LLM node output schema exposes `text``
- A `schedule` trigger-entry node must set an explicit `timezone` (e.g. Asia/Tokyo); Dify defaults schedule timezone to UTC when unset. — cite: `vendor/dify-src — schedule trigger timezone defaults to UTC (Dify 1.15)`
- An llm node with a blank model (provider: '' / name: '') will fail at runtime with 'Model not exist' — a build instantiating a pattern must wire a model before publish/run. — cite: `docs/specs test-phase-runtime-gap: builder LLM nodes ship empty model -> 'Model not exist'`
- An end-node output whose value_selector targets an llm node must reference the `text` field (e.g. [<llm_id>, text]); any other field name (output/result) on an llm source is almost always a mis-wire that returns empty. — cite: `vendor/dify-src/incident-end-node-reads-llm-text-field`
- Every {{#<node_id>.<field>#}} reference in a prompt_template must resolve to an existing node id + variable in the same graph; an unresolved ref substitutes to empty silently rather than erroring. — cite: `vendor/dify-src/incident-prompt-ref-must-resolve`
